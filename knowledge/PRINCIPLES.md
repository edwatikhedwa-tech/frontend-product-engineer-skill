# Principles

## Product before pixels

Start with the user, job, decision, and constraint the interface must support. A polished surface cannot rescue an unclear information architecture or an unserved job.

## Intentional hierarchy

Every screen needs a clear primary action, a readable entry point, and a visible relationship between content and controls. Use scale, weight, contrast, position, and spacing deliberately; do not make every label compete.

## Use real states

Design loading, empty, error, permission, partial-data, success, disabled, hover, focus, pressed, and long-content states when they can occur. A happy-path screenshot is not a product.

## System over decoration

Prefer a small coherent token and component system over one-off styling. Reuse is valuable when it preserves meaning, not when it forces unrelated content into the same shape.

## Evidence over confidence

A claim is incomplete until the relevant browser, screenshot, DOM, or accessibility evidence exists. A self-score is a summary, never proof.

## Accessible by default

Use native semantic elements, labels, logical focus order, visible focus, sufficient contrast, keyboard support, and text alternatives before adding ARIA. Test the actual interaction.

# Reference Research

Search by the product or UX problem, not by vague style terms such as “beautiful dashboard”, “modern SaaS”, or “premium UI”. Prefer queries such as CRM company list, customer directory, catalog search results, bulk actions table, filter builder, split view, settings navigation, profile, or data-heavy dashboard.

## Choose reference categories deliberately

Select only the categories that address the product’s actual design problem:

- **A. Product / UX reference** — workflow, jobs, decision points, and recovery.
- **B. Information architecture reference** — navigation, object model, grouping, hierarchy, and findability.
- **C. Visual / art direction reference** — composition, surfaces, rhythm, tone, and recognizable visual language.
- **D. Typography reference** — editorial/data roles, scale, line length, numerals, and hierarchy.
- **E. Interaction reference** — search, filters, selection, dialogs, feedback, and focus behavior.
- **F. Data-dense UI reference** — scanability, tables, density, comparison, and progressive disclosure.
- **G. Motion reference** — continuity, state change, gesture, or feedback when motion is relevant.

Do not use all categories by habit. State why each chosen category matters and why another category was not needed.

## Reference analysis

For every selected reference record:

- problem solved;
- relevant principle;
- why the hierarchy, spacing, or density works;
- interaction or visual language worth adapting;
- what not to copy;
- how to adapt it to the current product, users, content, and constraints.

References are benchmarks and reasoning sources. Do not pixel-copy, reproduce proprietary assets, or let a paid reference service become a hard dependency.

Then write a product design synthesis with information architecture, visual/art direction, typography, density/data presentation, interaction/motion, and product-specific signature.

The synthesis must describe a new product-specific system assembled from principles, not a clone of one reference.

If Refero, SaaSFrame, or another source is unavailable, use official design guidance, public product documentation, browser inspection, and a clear reasoning log. Lack of a named reference service must never block the skill.

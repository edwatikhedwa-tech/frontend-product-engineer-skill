# Review scorecard

Use findings, not a single self-score. For each dimension write evidence and defects.

| Dimension | Questions |
| --- | --- |
| Visual hierarchy | Can the user tell where to start and what matters? |
| Typography | Are roles, scale, contrast, wrapping, and line lengths readable? |
| Spacing/rhythm | Are relationships consistent and intentional? |
| Alignment | Do meaningful edges and columns line up? |
| Information architecture | Does grouping match the user’s mental model? |
| Density/scanability | Is the amount of information right for the job and viewport? |
| Affordance | Can users predict what controls do? |
| Consistency | Do shared components behave and look alike? |
| Responsive behavior | Does the strategy work at intermediate widths and mobile? |
| Interaction quality | Are feedback, errors, focus, loading, and recovery useful? |
| Accessibility | Are semantics, keyboard, focus, labels, and contrast adequate? |
| States | Are empty, error, permission, and long-content states designed? |
| Visual noise | Can borders, cards, badges, shadows, or decoration be removed? |
| Perceived polish | Does the result feel deliberate under real use? |
| Content robustness | Do realistic and stress values preserve usability? |

End with P0/P1/P2/P3 counts and evidence links. A 9/10 statement without evidence is not a passing review.

# Review scorecard

Use findings and evidence, not a single self-score. Mark each dimension WEAK, ACCEPTABLE, STRONG, or EXCEPTIONAL, then attach evidence and defects. WEAK or ACCEPTABLE on a critical design dimension requires another iteration.

## Engineering and UX quality

| Dimension | Questions | Evidence |
| --- | --- | --- |
| Functionality | Does the requested flow work in the real app? |  |
| Navigation | Can the user enter, orient, and recover? |  |
| Information architecture | Does grouping match the user’s mental model? |  |
| Visual hierarchy | Can the user tell where to start and what matters? |  |
| Spacing/rhythm | Are relationships consistent and intentional? |  |
| Alignment | Do meaningful edges and columns line up? |  |
| Density/scanability | Is the information amount right for the job and viewport? |  |
| Affordance/interaction | Can users predict controls and feedback? |  |
| Component consistency | Do shared components behave and look alike? |  |
| States | Are empty, error, loading, permission, and recovery states useful? |  |
| Responsive behavior | Does the strategy work at intermediate widths and mobile? |  |
| Accessibility | Are semantics, keyboard, focus, labels, and contrast adequate? |  |
| Content robustness | Do realistic and stress values preserve usability? |  |
| Overflow/regression | Are clipping, overlap, scroll, and neighboring flows verified? |  |

## Design quality

| Dimension | Questions | Evidence |
| --- | --- | --- |
| Visual identity | Can the product be described in one visual-language paragraph and recognized without its logo? |  |
| Distinctiveness | What prevents this from being a generic AI-generated SaaS dashboard? |  |
| Composition | Do space, alignment, scale, and surfaces express the product job? |  |
| Typography | Are type roles, editorial/data treatment, line length, and numerals intentional? |  |
| Art direction | Is there a coherent visual thesis rather than a token list? |  |
| Product personality | Does the interface have an appropriate character for its users and context? |  |
| Intentionality | Can major visual choices be justified by product/user/task rationale? |  |
| Restraint | Is there no unnecessary decoration, novelty, or component-library default styling? |  |
| Polish | Does the rendered result feel deliberate across states and viewports? |  |
| Design ambition | Is this the best interface the product could reasonably have within constraints? |  |

## Transformation quality

For REDESIGN, link the BEFORE → AFTER matrix and record:

- what materially changed;
- what improved in hierarchy, composition, visual language, interaction, density, and personality;
- what intentionally remained;
- why the result is not merely a tidy token restyle;
- whether missing BEFORE evidence prevents a conclusion.

End with P0/P1/P2/P3 counts and evidence links. A 9/10 statement or EXCEPTIONAL label without evidence is not a passing review.

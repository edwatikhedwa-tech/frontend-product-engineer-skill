# CREATE workflow

Use when the product or screen is new.

1. **Understand product** — write user, job, constraints, success criteria, and important states.
2. **Information architecture** — define objects, navigation, content priority, and the smallest useful flow.
3. **Reference research** — search comparable product and UX problems; record reasoning and what not to copy.
4. **Design direction** — write personality, hierarchy, typography, spacing, surfaces, responsive strategy, and interaction principles.
5. **Design system** — create a project `DESIGN.md` when the work is substantial enough to need durable tokens and component principles.
6. **Implement** — build a coherent slice with real content and non-happy-path states.
7. **Run** — start the actual application using the project’s documented workflow.
8. **Screenshots** — capture the viewport matrix and relevant states.
9. **Review** — switch to independent reviewer mode; inspect hierarchy, density, responsive behavior, accessibility, content stress, and polish.
10. **Fix and recheck** — remove P0/P1/P2 defects, capture evidence again, and run regression checks.
11. **Done** — report evidence, remaining P3 items, and anything not verified.

Do not start by generating random cards or a decorative dashboard with no user job.

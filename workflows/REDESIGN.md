# REDESIGN workflow

Use when an existing interface needs meaningful improvement.

1. **Discover the entire product** — map routes, important screens, shared navigation, design tokens, components, and data states.
2. **Run the current app** — use the real start command and record any setup assumptions.
3. **Screenshot important screens** — include desktop, intermediate, tablet/mobile where relevant, and important states.
4. **Audit** — identify structural, product, hierarchy, responsive, interaction, accessibility, and content problems.
5. **Research references** — compare product/UX solutions, not generic visual trends.
6. **Design direction** — define what changes systemically and what intentionally remains.
7. **Systemic redesign** — update shared tokens/components and representative flows before polishing isolated screens.
8. **Re-run and screenshot** — cover the same evidence set plus changed states.
9. **Independent review** — assume you did not create the interface; do not defend prior decisions.
10. **Fix P0/P1/P2 and regressions** — preserve working behavior unless scope explicitly changes it.
11. **Done** — report before/after evidence and unverified surfaces.

Do not redesign only the first screen shown by chance. Do not call a token restyle a redesign when the information architecture remains broken.

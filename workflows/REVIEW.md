# REVIEW workflow

Use when the user asks for an independent audit and has not asked for implementation.

1. Establish the review scope and success criteria.
2. Run the real app if possible; do not review source code alone.
3. Capture representative screens and relevant viewports/states.
4. Test realistic and stress content.
5. Inspect DOM overflow, clipping, scroll containers, focus, semantics, and accessibility evidence when tooling allows.
6. Review as an independent senior product designer, staff frontend engineer, and demanding product owner.
7. Record each finding with severity, location, evidence, impact, and recommended fix.
8. Summarize P0/P1/P2/P3 counts, strengths, limitations, and next actions.

Do not modify code unless the user explicitly changes the request from review to implementation.
